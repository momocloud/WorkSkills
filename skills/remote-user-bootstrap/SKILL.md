# 远端普通用户与 SSH 免密初始化（命令生成）

本 skill 用于解决“服务器目前只有 `root` 入口，但后续日常开发与其他工作流（如 `remote-npu-environment`）需要免密登录的普通用户”的问题。通过向用户收集必要参数，输出一套按执行端分段、可直接复制执行的分步命令与核对方法。

## 核心边界：只产出命令，不直接操作

- **绝不直接执行**：不得主动 SSH 连接远端服务器，不得在远端创建账号或修改配置，也不得在本机执行 `ssh-keygen`、写入 `~/.ssh/config` 或修改私钥/公钥文件。最终产物始终是给用户手动执行的分步命令清单。
- **不接触敏感凭据**：不向用户索要 `root` 密码、普通用户密码、SSH 私钥内容或令牌。命令中需要口令时保留交互输入（如 `passwd`）；需要公钥内容时使用清晰占位符（如 `<粘贴本机公钥整行内容>`）或给出由本机读取公钥的管道命令。
- **不预设固定环境**：不默认把家目录放在 `/home/<用户名>`（`/home` 分区空间可能不足），不假定远端发行版为 Ubuntu 或 CentOS，也不预设 `docker`、`HwHiAiUser` 等用户组已存在。

## 第一步：通过问答收集必要信息

先读取用户当前消息中已经给出的信息，**只询问缺失项**。将问题合并在 1–2 轮内问清，避免逐条零碎追问。核心需要确认四类信息：

1. **本机客户端环境与密钥方案**
   - 当前在本机使用哪种环境连接服务器？（Windows PowerShell / Windows Git Bash / WSL / Windows 与 WSL 两端都需要 / 原生 Linux / macOS）
   - 本机是否已有想复用的 SSH 密钥对（及公钥路径），还是需要新生成一对？
   - 是否需要同时生成 `~/.ssh/config` 别名配置？如需，期望的 `Host` 别名是什么？
2. **远端服务器信息**
   - 服务器地址（IP 或域名）、SSH 端口（默认 `22`）、是否经过跳板机（`ProxyJump`）？
   - 远端 Linux 发行版（如 Ubuntu/Debian、openEuler/CentOS/RHEL 等）？如果用户不清楚，先提供简短的只读探查命令。
3. **目标普通用户与家目录位置（重点确认）**
   - 期望创建的普通用户名是什么？
   - **家目录打算放在哪个路径？**（明确提醒：很多机器 `/home` 空间较小，可放到数据盘如 `/data/users/<用户名>`、`/home2/<用户名>` 等；若用户不确定哪个盘空间充足，先输出 `df -hT` 等只读检查命令，等用户确认路径后再生成建用户命令）
   - 默认 Shell 偏好（通常 `/bin/bash`），以及是否需要为该普通用户设置登录密码（例如用于 `sudo` 鉴权）还是仅允许 SSH 公钥登录？
4. **权限与附加组需求**
   - **Docker**：是否需要加入 `docker` 组？（提醒：`docker` 组具备接近 `root` 的主机控制能力）
   - **sudo 权限**：不需要 / 需要常规 `sudo`（输入密码）/ 需要免密 `NOPASSWD` / 仅限特定命令？
   - **硬件设备组（可选）**：是否需要访问昇腾 NPU、GPU 或其他设备组？若需要，先通过只读命令核对设备节点实际属组，再加入对应组。
   - **额外工作目录（可选）**：除家目录外，是否还有单独的数据盘目录需要创建并授权给该用户？

> 若用户暂时还不清楚远端磁盘布局、发行版或设备组，可先输出一段简短的「远端 root 只读探查命令」，让用户执行后贴回结果，再生成精确的最终命令；如果用户希望一次拿到完整步骤，也可以在明确标注前置检查项的前提下给出参数化命令。

生成最终命令前，读取对应参考文件以核对参数细节、跨发行版差异与常见踩坑点：

| 场景 | 参考文件 | 关注重点 |
| --- | --- | --- |
| 远端建用户、自定义家目录、加组、sudo、公钥写入 | [远端用户与权限配置](references/remote-user-setup.md) | 非 `/home` 父目录与 `StrictModes` 权限、SELinux 上下文、账号锁定态、`sudoers.d` 安全校验、`docker`/设备组核验、`sshd_config` 限制 |

## 第三步：最终产物的组织与交付标准

收集齐信息后，按**执行顺序**和**执行终端**分段输出完整命令，确保用户可以直接按块复制执行：

1. **参数摘要**：简短列出本次命令所依据的用户名、家目录路径、客户端系统、远端地址/端口、附加组与 `sudo` 策略，便于用户复核。
2. **阶段一：远端只读核查（在远端 `root` 终端执行）**（按需）
   - 核查磁盘挂载空间、发行版、用户名/目标家目录是否冲突、`docker`/设备组是否存在、`sshd` 是否有 `AllowUsers`/`AllowGroups` 限制及 SELinux 状态。
3. **阶段二：本机准备 SSH 密钥（在本机对应终端执行）**
   - 根据用户选择的系统（Windows PowerShell / WSL / 双端 / Linux / macOS）给出检查或生成密钥、查看公钥的命令。
4. **阶段三：远端创建用户、配置权限与写入公钥（在远端 `root` 终端执行）**
   - 依次完成：创建自定义家目录父路径并核对权限 → 创建用户 → 设置密码或解锁公钥登录 → 加入 `docker`/设备组 → 配置 `sudoers.d` 并用 `visudo -cf` 校验 → 幂等写入 `authorized_keys`（剔除 `\r`）并修正权限（以及必要时的 SELinux 上下文）。
   - **已确认的参数必须直接填入命令变量中**，不要留下本可替换的占位符；仅对需现场粘贴的内容（如公钥整行）保留明确占位符。
5. **阶段四：本机写入 SSH Config（在本机终端执行，如需要）**
   - 给出带别名、主机、端口、普通用户名、`IdentityFile`、`IdentitiesOnly yes`（及可选 `ProxyJump`）的安全写入命令。
6. **阶段五：验证与交接（在本机终端以普通用户执行）**
   - 给出不依赖 `root` 的端到端验证命令：免密登录（`BatchMode=yes`）、核对 `id` / `pwd` / 家目录可写性、以及按需验证 `docker ps`、`sudo -l` 或设备访问。
   - 附上 3–5 条最贴合本次场景的排障提示（如 `ssh -vvv`、非 `/home` 父目录权限、SELinux、WSL 密钥权限等）。
   - 验证通过后，即可退出 `root` 会话，使用该免密普通用户开展后续工作（如衔接 `remote-npu-environment`）。
