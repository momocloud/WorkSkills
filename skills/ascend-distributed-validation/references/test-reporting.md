# 结果报告与归档

## 从实际证据汇总

先识别输出结构和判定逻辑，再选择解析方式。可以使用已有框架产出的 JUnit、CSV、JSON 或文本，避免为报告强迫用例改接口。每项结果关联到本次实际命令和原始日志。

将下面这些结论分开；名称可适应项目，不要求固定状态枚举：

| 证据 | 报告含义 |
| --- | --- |
| 数值断言或明确正确性判据通过 | 对应覆盖范围内的正确性通过 |
| 仅采集耗时/带宽并正常完成 | 性能采集完成，不宣称精度通过 |
| 压力循环满足内存/耗时阈值 | 压力判据通过，不自动等于逐次数值校验 |
| 返回码为 0，但结果文件包含 FAIL/ERROR | 依据用例判据记录失败 |
| 程序只打印结果、未完整传播失败 | 说明判定不足，不仅凭退出码判通过 |
| 故障注入触发与设计吻合的异常 | 预期异常验证成功；不能把任意崩溃视为符合预期 |
| 异常中断、SKIP、资源阻塞、没有启动 | 分别记录，不计为已通过 |

原始退出码、运行器清理码和业务判定可以同时保存。CSV 已写完但清理崩溃的程序，不能只根据 CSV 宣称整个运行成功。汇总区分脚本数、启动次数、参数组合数和独立缺陷数。

## 报告内容与复现

按任务复杂度选择文档格式；有多份证据时可提供独立 HTML 和机器可读摘要，简单结果无需强制生成一套文件。需要时涵盖：

- 环境与源码身份、覆盖范围、执行时间及结果概览。
- 各项参数、实际命令、工作目录、环境覆盖、退出状态和判据；未执行和 SKIP 原因。
- 失败现象、首个异常、对应原始日志/行号、初步原因和尚未证明的部分。
- 性能测量口径、单位、预热和迭代；无完整数据时不补造表格。
- 成功和失败项的人工复现方式，以及与其他环境或历史记录的可比范围。

人工复现命令从实际执行记录和当前用例说明产生，不凭技能固定生成 `python` 或 `torchrun`。保留影响行为的参数和顺序；输出位置、临时端口等改动需注明，并先确认入口支持这些参数。必要时包含激活环境、设备/端口检查、退出码及产物检查和仅针对本次任务的收尾。

引用环境差异时写实际证据。不能因同为“9.x”就声称二进制一致，也不能仅凭相同错误码把不同运行归为同一根因。多 rank 日志可能交错、快照时刻可能不同；不能依赖显示先后来判定首个出错 rank。

## 交付检查与保留

核对统计能回溯原始记录，报告引用能离线定位；人工命令可做语法检查，但语法通过不等于已重跑成功。若生成器需要环境清单、对照结果等材料，将必要副本纳入交付，避免依赖后来会删除的临时目录。

归档清理仅在用户要求的范围内进行：先清点并生成完整归档，校验归档与源文件一致，再移除选定的旧记录。保留归档清单和校验值，更新索引；清理后检查保留报告的链接和必要依赖。不要因为生成新报告就自动删除原始日志或旧结果。
