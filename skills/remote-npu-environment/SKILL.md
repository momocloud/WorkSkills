# 远端 NPU 环境管理

完成用户指定机器上的连接、环境准备或恢复工作，并保存可复现记录。本 skill 不固定 IP、账号、目录、硬件或软件版本；不依赖原工作区中的约定文件。仅编写方案或文档时不主动连接机器、创建账号或安装软件。

## 先确定目标和版本

先读取当前任务与会话中的已有选择，收集目标主机/SSH 别名、端口/跳板机、普通账号、认证方式、工作根目录、任务目录和环境选择。按机器分别记录，不从无关任务继承账号或授权；只询问影响下一步且缺失的信息。

**实际使用或新建、重建、切换框架环境前，若当前任务未明确版本或指定已有环境，必须先向用户询问 PyTorch 和 torch-npu 分别使用哪个版本。** 可以这样问：

> 这次要复用哪套已有环境，还是重新安装？PyTorch 和 torch-npu 分别使用哪个版本？也可以指定一份历史环境记录或锁文件；Python 和 CANN 如有要求请一起说明。

- 用户已明确指定环境、锁文件或精确版本时沿用选择，不因换会话重复询问。“重装一下”不等于授权沿用历史版本；“最新版”须解析为当时可获得且兼容的具体版本并记录。
- 只指定 PyTorch 时，核对配套 torch-npu 后请用户确认；已有代选配套版本的授权时可自行决定并记录依据。不能用版本号相同推断兼容。
- 核对所选版本对应的官方 Python、架构、系统、驱动、CANN/算子包和框架兼容说明。目标不兼容或制品缺失时说明冲突，请用户决定，不静默换版本。
- 等待版本选择时可检查连接和系统现状；不得先安装、升级或替换框架。纯连接排查不要求用户先选框架版本。

## 操作边界

- 日常安装与任务执行直接以普通用户登录。不因连接失败自动改用 root，也不通过 root 登录后切换用户执行任务。
- 创建账号和配置设备访问是独立的管理员初始化操作。只有用户已明确授权目标机器上的相应范围且提供可用管理员入口时才由 agent 执行；已有授权不重复询问。没有入口则给出缺失项及管理员操作步骤，不绕过权限。
- 默认按共享机器使用。任务源码、依赖、虚拟环境、安装包、日志、报告、缓存和临时文件都放在核实的工作根目录内；不写远端 `/tmp`、`/root` 或其他成员目录。检查工具专用输出以及容器挂载、符号链接的实际落点；不重定义 `HOME`。
- 除明确授权的系统管理步骤外，不修改系统配置或驱动、不全局安装、不重启机器或重置设备。不得停止或修改其他成员的进程、容器和环境；同账号资源也可能属于其他任务。Docker 能力不扩大操作权限。
- **项目级隔离与可识别标识**：
  - **项目间严格隔离**：不同项目/需求各自使用带清晰项目标识的独立 Python 虚拟环境，不得复用来源不明或属于其他项目的环境，避免同时推进多个项目时相互污染。
  - **项目内可识别与核实后复用**：新建前先排查远端是否存在能明确识别为属于**当前项目**的环境（通过项目目录归属、含项目标识的命名、激活脚本及环境标识元信息确认）；仅在确认归属当前项目、解释器与依赖完整、且与目标版本一致时复用，方便多个 agent 协同推进同一项目。
  - **无法识别时新建带标识的隔离环境**：若不存在可确认为当前项目的环境，或已有环境不满足复用条件，则为当前项目新建带项目与版本标识的隔离环境，并落盘清晰的归属标识与激活入口，使同项目后续或并行的其他 agent 能够直接发现。
  - **不原地破坏共享中的项目环境**：同项目内多 agent 复用已验证环境时仅做只读使用；需要切换/升级依赖版本时另建新标识环境，不覆盖已验证环境或改写其他任务共用的默认入口。用 uv 安装到明确指定的虚拟环境；不用 `uv pip install --system`，保留 `PIP_REQUIRE_VIRTUALENV=true`。
- 不把密码、私钥、令牌写入技能、任务文件或日志。每次连接重试应基于新证据；无法在已知连接信息和权限内继续时，说明错误及所需补充信息，不无限重试。

## 验证与交付

每次使用 NPU 前重新检查设备健康与占用，显式设置 `ASCEND_RT_VISIBLE_DEVICES` 和卡数；历史设备状态不是预留。分布式测试避免端口/会合冲突，设置通信和进程超时，失败后只清理本任务资源。

按任务需要验证新会话激活、解释器和包版本、导入、单卡计算及多卡 HCCL。无空闲设备时标记待验证。区分“已安装”“导入通过”“单卡通过”“多卡通过”与任务验收；不能用旧记录替代恢复后的验证。

交付时说明机器与环境选择、实际完成的操作、验证证据和待处理项，给出激活入口和持久化复现材料位置。即使同一 IP 仍可访问，重装后也重新核对身份、目录、系统、驱动和运行状态。
